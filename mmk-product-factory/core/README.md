# MMK PRODUCT FACTORY CORE

## Purpose

The MMK Product Factory is the controlled production environment for
creating, testing, packaging, preserving and reusing MMK products.

MMK products are built as connected layers:

DIGITAL ASSET → SYSTEM → SOFTWARE → API → SaaS

---

## MMK PRODUCT FACTORY PROTOCOL

Every asset and product must follow this lifecycle:

1. OWNER IDEA
2. PLAN
3. BUILD
4. CHECK
5. TEST
6. FIX / IMPROVE
7. CHECK AGAIN
8. TEST AGAIN
9. PACKAGE
10. PRESERVE
11. REUSE / CONNECT

No product skips the lifecycle.

---

## 01 — DIGITAL ASSETS

Digital assets include:

- Design Packs
- Business Templates
- Social Media Kits
- Documents
- Creative Resources
- Brand Resources

Digital assets must be organized, versioned and reusable.

---

## 02 — SYSTEMS

MMK systems include:

- Ordering System
- Stock System
- KPI System
- Security System

Systems should be designed so they can become reusable software products.

---

## 03 — SOFTWARE

MMK software includes:

- Web Apps
- Mobile-ready Apps
- Desktop Tools

Software must be tested in its real working environment before release.

---

## 04 — APIs

MMK APIs include:

- Authentication
- Products
- Orders
- Stock
- Reports

APIs should expose reusable functionality from MMK systems and software.

---

## 05 — SaaS

MMK SaaS products include:

- Multi-business platforms
- Accounts
- Subscriptions
- Cloud Services

SaaS products should reuse stable MMK systems, software and APIs.

---

## PRODUCT CONNECTION

Products should not be isolated whenever reuse is practical.

Example:

Stock Asset
→ Stock System
→ Stock Software
→ Stock API
→ Stock SaaS

The same principle applies to ordering, KPI, security and other MMK
product families.

---

## QUALITY RULE

A product is not considered complete merely because its files exist.

Completion requires:

BUILD
→ CHECK
→ TEST
→ FIX / IMPROVE
→ CHECK
→ TEST
→ PACKAGE
→ PRESERVE

---

## VERSIONING

Approved products must have:

- Product name
- Version
- README
- Customer documentation where appropriate
- Test/check record where appropriate
- Release location
- Preservation/backup strategy

---

## SECURITY

Security must be considered throughout the lifecycle.

Do not expose:

- Secrets
- API keys
- Passwords
- Private credentials
- Production databases
- Sensitive customer information

Development data and production data must be treated separately.

---

## DEVELOPMENT PRINCIPLE

Git, GitHub, CI/CD, automation, DevOps and security tools support the
MMK Product Factory.

They do not replace product development.

The product itself must always remain the primary focus.

---

## OWNER CONTROL

The MMK owner controls:

- Product direction
- Product purpose
- Major changes
- Approval for release
- Final product decisions

The factory assists with planning, building, checking, testing,
documentation and preservation.

---

## MMK FACTORY PRINCIPLE

BUILD ONCE.
BUILD CORRECTLY.
TEST IN THE REAL PRODUCT.
IMPROVE.
PACKAGE.
PRESERVE.
REUSE.
SCALE.
