# MMK DIGITAL FACTORY — FACTORY RULES

## Internal Build v0.1

These rules govern how MMK Digital Factory creates, manages, tests, releases and preserves work.

---

## RULE 01 — OWNER CONTROL

MMK remains responsible for Factory direction, priorities, approvals and commercial decisions.

Members participate through defined opportunities, roles and agreements.

---

## RULE 02 — NO OPPORTUNITY WITHOUT A RECORD

Every Factory opportunity must have an Opportunity record.

At minimum:

- Opportunity ID
- title
- description
- category
- source
- owner
- status
- date created

---

## RULE 03 — NO PRODUCTION WITHOUT A PLAN

An approved opportunity must have a production plan before manufacturing begins.

The plan should identify:

- expected outcome
- required skills
- resources
- responsible person
- production stages
- quality requirements
- expected completion condition

---

## RULE 04 — BUILD BEFORE RELEASE

A product or service is not considered ready merely because development has started.

It must pass the applicable manufacturing and quality stages.

---

## RULE 05 — QUALITY GATE

Every release must pass a documented quality check appropriate to the product or service.

A failed quality check sends the work back for correction.

---

## RULE 06 — VERSION EVERYTHING THAT CHANGES

Products, software, documents and other versioned Factory assets should have identifiable versions.

Changes should be traceable where practical.

---

## RULE 07 — PRESERVE WORK

Important Factory work must be preserved.

Where appropriate, preservation includes:

- source files
- documentation
- tests
- release package
- version information
- backups
- intellectual-property information

---

## RULE 08 — PROTECT EXISTING MMK ASSETS

Factory development must not casually delete, overwrite, move or modify unrelated MMK products, assets or departments.

Existing work must be inspected before changes are made.

Destructive commands require deliberate verification.

---

## RULE 09 — MEMBER WORK MUST BE LEGITIMATE

Members may participate only in legitimate activities that comply with applicable laws, platform rules and agreed commercial arrangements.

No member should be promised payment without a defined commercial arrangement.

---

## RULE 10 — SKILLS SHOULD BECOME REUSABLE KNOWLEDGE

When suitable, completed production work should produce reusable:

- documentation
- SOPs
- checklists
- training
- examples
- lessons learned

---

## RULE 11 — PORTFOLIO VALUE

Where appropriate and permitted, member participation should create evidence of skills and completed work that members can use to build portfolios.

Sensitive customer information and confidential intellectual property must not be exposed without permission.

---

## RULE 12 — CUSTOMER PROTECTION

Customer work must be clearly defined.

Before delivery, the Factory should understand:

- what was requested
- what will be delivered
- applicable price
- expected timeframe
- responsibilities
- important limitations
- support/maintenance terms where applicable

---

## RULE 13 — INTELLECTUAL PROPERTY

Before commercial release, the Factory should identify:

- creator/contributor
- ownership
- licences
- third-party assets
- dependencies
- usage restrictions
- commercial permissions

Do not claim ownership of material that MMK does not own or have permission to use.

---

## RULE 14 — SECURITY

Sensitive information must not be placed casually into source code, public repositories or public demonstrations.

Secrets such as passwords, API keys and private credentials must remain outside committed source files.

---

## RULE 15 — TEST REAL PRODUCTS

Where practical, Factory products must be tested in the environment in which customers will actually use them.

Examples:

- browser
- Android device
- local network
- deployed website
- customer workflow

---

## RULE 16 — DOCUMENT FAILURES

A failed test is useful Factory information.

Important failures should be recorded so the same problem is less likely to happen again.

---

## RULE 17 — IMPROVEMENT LOOP

The Factory operates continuously:

BUILD
→ CHECK
→ TEST
→ FIX
→ IMPROVE
→ TEST AGAIN
→ PACKAGE
→ PRESERVE

---

## RULE 18 — COMMERCIAL CLARITY

MMK revenue may come from legitimate:

- products
- services
- Factory access
- licensing
- subscriptions
- training
- partnerships
- other approved commercial activities

Commercial terms should be defined before delivery or paid participation where applicable.

---

## RULE 19 — DASHBOARD IS A CONTROL SYSTEM

The Factory Dashboard must represent actual Factory records.

It must not become a collection of fake numbers or decorative statistics.

Future dashboard metrics should be derived from real records.

---

## RULE 20 — START SMALL, BUILD THE MACHINE

The first version should solve the core Factory workflow before adding unnecessary complexity.

The goal of v0.1 is a working internal machine, not a giant platform.
